# Fcitx5 候选窗口统一 UI 开发方案

评估日期：2026-09-15。代码基线：`d66b78d`。首个验证环境：Ubuntu 26.04、GNOME Shell 50.1、Wayland、Fcitx5 5.1.19。

本文件描述完整开发计划。2026-09-16 已实施阶段 1 的纯 Rust 离线渲染器，见 [共享渲染设计](../design/rendering.md)；阶段 0 已有受开关保护的 XCB 窗口原型；阶段 2 已接 C ABI、配置、回退、交互和曝光协议，并补齐配置、主题、几何、鼠标事件与生命周期回归。当前 Rust 424 项测试、普通构建 24 项 CTest、实验构建 26 项 CTest 均通过，含真实 X server 窗口冒烟。阶段 0 的逐应用通过条件与阶段 3 的真实桌面验收仍未完成，不能标为完整交付；当前覆盖见 [支持矩阵](../notes/linux-ui-support.md)。已有输入法接入见 [Fcitx5 支持方案](fcitx5_support_plan.md)，构建与验证记录见 [Linux 工程记录](../notes/linux-fcitx5.md)。

## 1. 是否具备开发条件

**具备启动开发的条件，未发现阻止原型和渲染开发的确定性阻塞。完整替换 GNOME/Wayland 下所有候选面板，仍有一项必须先验证的技术关卡：窗口承载与定位。**

| 项目 | 当前证据 | 对开发的影响 |
|---|---|---|
| Fcitx5 输入链路 | 已有 C++ 插件、Rust Server、Unix socket、候选选择与会话测试；用户反馈已能实际输入 | 直接复用 |
| UI 所需内容 | `Frame` 已包含候选、释义、拼音分段、光标、高亮、页码、布局、主题 | 不需要重写查询、排序或学习 |
| 自定义面板入口 | 本机头文件有 `setCustomInputPanelCallback()` | 可以为青简上下文接管面板，无需先替换全局 UI addon |
| 现有视觉参考 | macOS、Windows 各有主题、候选行和绘制代码 | 可以复用设计规则，平台绘制调用不能直接跨平台使用 |
| 共享渲染器 | 计划评估时检出不存在共享渲染器；现已新增阶段 1 crate 与正式设计 | 阶段 1 已有离线实现，窗口集成仍待后续阶段 |
| GNOME/Wayland 定位 | 自定义回调会绕过客户端候选面板，普通 Wayland 窗口没有任意全局定位能力 | 阶段 0 必须实测，不得直接承诺全场景可用 |

如果要求“所有原生 Wayland 应用及 GNOME Shell 搜索框都完全自绘、不得回退、不得安装扩展”，现阶段证据不足以确认满足该要求。可以开发，但必须先得到窗口原型的结果；不能把这个条件写成已解决。

本方案将范围定为：**在验证通过的场景使用青简自绘 UI，其余场景保持已有 Fcitx 面板可用，并准确报告覆盖范围。** 回退代表兼容性保障，不计为该场景已经实现统一 UI。

## 2. 成果与范围

目标是统一布局、视觉层级和交互，系统字体栅格化差异允许存在。先交付 Linux 候选窗，macOS / Windows 整体迁移到共享渲染器不作为前置条件。

| 内容 | 目标行为 |
|---|---|
| 竖排 | 序号、候选词、译词分别对齐；高亮覆盖整行 |
| 横排 | 候选横向排列，下方只显示当前高亮项的译词，保留页码 |
| 字体层级 | 候选词 16、译词 12、序号 11 逻辑像素，按输出缩放换算 |
| 释义 | 同一辅助语言的词性、释义和日文读音按展示片段绘制；不再只取第一条释义 |
| 生词 | `Sense::fresh` 控制橙色，移除自绘模式中的“· 生”文字标记 |
| 拼音 | 显示光标、未输入完部分和纠错删除线，保留应用内 preedit |
| 外观 | 浅色 / 深色、圆角、阴影、淡蓝高亮、8 像素内边距、4 像素行内留白 |
| 长内容 | 按屏幕可用区域限制尺寸，按文本簇截断；原始候选和上屏内容保持完整 |
| 鼠标 | 点选、翻页、滚轮行为与数字键及已有分页一致，稀疏候选空槽不能被选中 |

配色优先参考 [Windows Palette](../../apps/windows/server/src/ui/candidates/theme/palette.rs)，布局参考 [候选窗口设计](../design/candidate-ui.md) 与 [macOS Theme](../../apps/macos/src/candidates/theme.rs)。冻结浅 / 深、横 / 竖的参考图后再实现，不能把不同平台当前所有细节都当成同时必须满足的标准。

本次不扩展云联想、神经重排、选区翻译、设置 GUI、悬浮状态条；只为已有 `Frame` 中的可选字段保留显示能力，不伪造尚未启用功能的内容。

## 3. 技术事实与路线选择

### 3.1 自定义回调的边界

Fcitx5 从 5.0.24 提供 `InputPanel::setCustomInputPanelCallback()`，本机版本满足要求。回调取代通常的候选面板更新路径，但 `updatePreedit()` 仍能发送应用内 preedit；`InputPanel::reset()` 会清除回调。因此当前插件每帧执行 `panel.reset()` 后必须重新设置回调，隐藏自绘窗也不能只依赖 `reset()`。[官方接口](https://github.com/fcitx/fcitx5/blob/5.1.19/src/lib/fcitx/inputpanel.h)、[reset 实现](https://github.com/fcitx/fcitx5/blob/5.1.19/src/lib/fcitx/inputpanel.cpp)。

该入口只解决“谁负责显示”，不会自动提供窗口、可靠坐标或客户端画布。虚拟键盘等更高优先级显示路径也需保持正常。不得为了接管青简而关闭其他输入法的 UI。

### 3.2 Wayland 验证范围

Fcitx 的 GTK/Qt 前端可能在应用内部画候选窗，以解决 Wayland 定位；自定义回调会绕过这条路径。XWayland、Wayland 输入法专用 popup 和 GNOME Shell 扩展是不同承载路线，不能只检查 `XDG_SESSION_TYPE` 就决定使用哪一种。[官方 Wayland 说明](https://fcitx-im.org/wiki/Using_Fcitx_5_on_Wayland/en)。

| 场景 | 原型优先路线 | 通过前的处理 |
|---|---|---|
| X11 / XWayland 应用 | Fcitx 插件侧的非激活 XCB 窗口，核对实际光标坐标与缩放 | 默认面板 |
| 支持输入法 popup 的 Wayland 前端 | 验证能否经 Fcitx 现有连接和公开模块接口取得适用 surface role | 默认面板；不另起进程抢占输入法角色 |
| GNOME 原生 Wayland GTK/Qt/Electron | 逐应用验证坐标来源；需要时评估 Shell 扩展或客户端呈现协作 | 默认面板；XWayland 浮窗不能被视为通用解决方案 |
| GNOME Shell 搜索等界面 | 评估 Shell 内部呈现，借鉴 Kimpanel 的接入边界 | 不承诺独立普通窗口能覆盖 |

不能用固定位置、最大化窗口下的偶然对齐或鼠标位置代替光标跟随验收。官方文档是机制参考；当前 GNOME 50.1 的实际能力必须以本机记录为准。

### 3.3 采用的路线

主线采用 **青简上下文的自定义回调 + 平台无关位图渲染器 + 按场景选择的窗口后端**。保留现有 Fcitx 面板作为回退。

不把“更换皮肤”当作统一 UI 的完成标准。Fcitx Classic UI 已支持译词字号比例、译词颜色和背景图，可用于回退模式的外观改善，但主题不提供任意逐片段样式，而且可能影响其他输入法。[主题定义](https://github.com/fcitx/fcitx5/blob/5.1.19/src/ui/classic/theme.h)。

## 4. 模块与数据流

```text
qingjian-linux-server：Engine、学习、隐私、候选顺序
                  │ 现有 Frame
                  ▼
Fcitx5 QingjianEngine：保存当前上下文及 revision
                  │
          Linux PanelController
            ┌─────┴───────────┐
            ▼                 ▼
   已验证的自绘后端        现有 Fcitx 面板
            │
   render-ffi → qingjian-render
            │
   像素、尺寸、点击区域 → 窗口贴图

点击 / 翻页 → 验证上下文与 revision → 现有选词通路 → Server
```

窗口生命周期放在 Fcitx 侧，与 InputContext 一起处理。Server 继续提供候选内容，不把绘图或窗口创建放进按键响应，也不新增每帧图片的 JSON/socket 往返。

模块目录（其中 `crates/qingjian-render` 已实现阶段 1，其余已落地实验实现但尚未通过桌面验收）：

| 位置 | 职责 |
|---|---|
| `crates/qingjian-render/` | 展示模型、主题、测量排版、字体缓存、位图与点击区域；不调用桌面 API |
| `apps/linux/render-ffi/` | 仅绘制的 C ABI，接收现有 Frame 的序列化视图并返回渲染结果 |
| `apps/linux/fcitx5/src/panel/` | 当前帧、回调、后端选择、回退和显示生命周期 |
| `apps/linux/fcitx5/src/panel/backend/` | 窗口创建、定位、缩放与输入区域，先落地阶段 0 通过的后端 |
| `apps/linux/fcitx5/src/panel/interaction/` | 点击区域到已有选词 / 翻页操作的映射 |

若后续证明 GNOME 必须依靠扩展才能达到约定覆盖范围，再增加独立的 GNOME 展示适配器，先验证 GNOME 50 接口和安装路径；不要提前把扩展当作已有依赖。该路径可能需要专门的帧传输，不套用上图中的进程内 C ABI。

绘制库不能创建 Engine、查询词库、重新排序、改写上屏文本或判断生词。只做展示格式化，例如消费 `fresh`、词性和读音。共享模型应收敛现有两端 `Row` / `Tone` 的表达，不引入第三套候选业务模型。

## 5. 渲染与接口约定

### 5.1 初始实现选择

推荐 CPU 位图方案：`tiny-skia` 绘制背景、高亮和阴影，`cosmic-text` 负责文本整形、字体回退和栅格化。二者均有 Rust 实现，适合作为不依赖平台窗口的起点；CJK、日文和 emoji 的实际显示仍需样例验证。[tiny-skia](https://github.com/linebender/tiny-skia)、[cosmic-text](https://github.com/pop-os/cosmic-text)。

版本在实施时用 `cargo add` 选取与仓库 Rust 1.96.0 兼容的组合并锁定；不因渲染依赖自动提升全仓库工具链。先核对是否能取得 `renderer-spike` 的具体内容，不能取得就按本方案新建，不从说明中的名称推断已有实现。

测量和绘制必须使用同一字体、字号、缩放与整形结果。优先系统 sans-serif 和 CJK 回退；不用 macOS 或 Windows 专有字体文件。测试固定有明确许可的字体，实际运行缺字时仍要有回退。对位图声明像素顺序、预乘 alpha、stride 和物理尺寸，窗口后端显式转换格式，不能把 RGBA 与 BGRA 混用。

### 5.2 C ABI 与内存

`render-ffi` 优先构建为静态库链接进 addon；这里只嵌入绘制能力，Engine 仍隔离在 Server。接口采用不透明 renderer/result 句柄：初始化、渲染、查询像素及点击区域、释放结果、销毁 renderer。

传入数据使用指针和长度，带 ABI 版本；输入 Frame、缩放与尺寸上限由边界统一校验。结果由 Rust 分配并通过配套函数释放，C++ 在贴图生命周期结束前保有结果，不能混用分配器。Rust panic 在 FFI 入口转换成失败结果，C++ 异常不跨边界。

这只能隔离可捕获错误，不能保证进程内渲染的非法内存访问或进程终止不影响 Fcitx。失败时回退默认面板；若原型暴露必须进程隔离的稳定性问题，再单独评估展示进程及传输成本。

### 5.3 帧、事件与回退

- 展示帧标识使用“连接代次 + InputContext 身份 + revision”。当前 `Session::id` 在每条连接里都为 1，不能拿它作为跨上下文唯一窗口标识。
- 渲染完成、点击和定时刷新前均确认上下文仍存在、仍是青简、仍有焦点且 revision 匹配。旧帧只能丢弃，不能重新上屏。
- 每次 `panel.reset()` 后，先恢复必要的 preedit 和候选信息，再按后端重新注册自定义回调。
- Fcitx 默认面板与自绘面板同时只能显示一个。接管前主动隐藏旧面板；回退时先隐藏自绘窗、解除回调，再用当前有效帧刷新默认面板。仅设置回调不能证明旧窗口已消失。
- UI 显隐不等于组句结束。保持现有 `commitRaw()`、`clientPreedit` 失焦提交判定和隐私清理顺序，不能因回退重新 Commit 或重复记录学习。
- 空候选保留原数字槽位，点击阴影、不可选槽位和旧页均无效。尺寸截断只改显示，提交仍引用完整候选。
- 隐私能力变化、断线、reset、deactivate、上下文销毁时，同步隐藏窗口并作废暂存帧。默认日志不写候选文本，截图只用固定测试语句。

## 6. 配置、学习记录与性能

继续使用现有 `[general] layout`、`theme`、`preedit`、`page_size` 和 `[shortcut]`；UI 不改变按键规则。新增配置拟放同一份 `config.toml` 的 `[linux_ui]`：`renderer = "fcitx" | "auto" | "qingjian"`。

- `fcitx`：强制现有面板，用于立即回退。
- `auto`：只在后端能力及验收规则明确支持时自绘，其余走默认面板。
- `qingjian`：优先请求自绘；无法创建窗口仍回退并记原因，不强行显示位置错误的窗口。

实验期默认 `fcitx`，桌面验收通过后才考虑 `auto`。Server 是配置读取方，通过 Linux 的显示初始化信息传给插件；需要扩展消息时明确 Linux 协议版本和失败行为，不悄悄改变现有 Windows 协议。第一版沿用配置修改后重启生效。

生词颜色来自 Core。若横排只展示高亮项译词，而当前曝光记录按整页统计，需补充按实际展示译词记录的通路，并携带帧标识；不能让两个显示后端各记一次。默认面板跨前端的曝光确认精度需记录，不能宣称已严格测量用户看到的内容。任何调整继续满足普通输入与私密输入隔离。

建立新增 UI 开销的独立基线：记录 Frame 就绪到显示提交、整形、位图和贴图的耗时，覆盖冷启动与预热后 p50/p95/p99。初始目标是本机预热后新增 UI 工作 p95 ≤ 5 ms、p99 ≤ 10 ms，属于待验证目标，不是现有测量结果。

字体扫描与缓存初始化在启用前完成，未就绪时保留默认面板。按内容、主题和缩放缓存结果，不能在每键重建字体库。现有 `Connection::send()` 虽使用非阻塞 fd，内部仍同步 `poll` 等待、共享截止时间为 200 ms；它并非完全异步事件循环。总延迟必须将这部分单独计入，不能归因于自绘或通过增加更长同步等待掩盖问题。

## 7. 实施阶段与通过条件

### 阶段 0：窗口承载原型，1–2 个工作日起步

使用固定测试内容，不接整套渲染库。记录当前各应用的前端、ClientSideInputPanel 能力、坐标系和缩放；测试非激活窗口及自定义回调；对 GNOME 原生场景先判定能否使用已知后端。

交付一张应用 / 后端支持表、固定语句截图、失焦与回退记录。窗口必须跟随移动和调整大小后的应用、不过屏幕边界、不抢焦点、鼠标可选、不双窗、失焦隐藏、切换输入法恢复正常。

**决策点：** 用户常用的浏览器、编辑器和终端有可靠承载路线，才推进这些场景的自绘集成；未通过的场景保留默认面板。若原生 GNOME 必须扩展且暂不能实现，明确这是其统一 UI 的阶段性阻塞，不把 XWayland 原型通过写成 GNOME 全覆盖。渲染器开发仍可继续。

### 阶段 1：渲染器与视觉样例，3–5 个工作日

建立展示模型、主题、横竖排、字体和位图输出；冻结参考图并实现独立离线渲染工具。样例包含长候选、缺释义、中英日混排、emoji、生词、纠错、空槽、页尾及屏幕窄宽。

通过条件：所有样例不裁字、不串列；明暗外观可读；同一字体和缩放下结果稳定；渲染输出与点击区域一致。此阶段不以窗口协议为前置条件。

### 阶段 2：Fcitx 集成与回退，3–5 个工作日

接 C ABI、PanelController、已验证的窗口后端和真实 Frame。完成鼠标、分页、配置、缩放、回调重建、默认 UI 隐藏和回退；核对曝光记录及隐私状态。

通过条件：核心输入结果与原版一致；已有生命周期和隐私回归通过；渲染失败、Server 重启、上下文销毁均不遗留窗口或错上屏；两个模式可切换且其他输入法不受影响。

### 阶段 3：桌面验收与打包，2–4 个工作日

完成下表、性能记录、安装 / 卸载及构建依赖说明。分别标记“自绘通过”“默认回退”“未验证”“失败”，不使用一个总勾选掩盖覆盖差异。

通过条件：声明支持的每种应用路径有真实验收记录；全新用户目录能安装；卸载不删除用户数据；默认 UI 可恢复。未验证 GNOME 搜索框时，不将其写入支持范围。

### 后续独立任务

GNOME 展示扩展、GTK/Qt 客户端适配、其他桌面后端、macOS/Windows 迁移共享渲染器均单独立项。上面合计约 9–16 个工作日，是单人开发与本机验证估算，不包含这些扩展任务；阶段 0 若发现必要后端缺失，应重估覆盖范围和时间。

## 8. 验证矩阵与检查

| 维度 | 必测内容 |
|---|---|
| 应用 | GTK 编辑器、浏览器、Qt 应用、Electron 编辑器、终端；逐项记录版本及真实 XWayland / Wayland 路径 |
| 桌面 | GNOME 原生应用与 GNOME Shell 搜索单列，不能互相替代 |
| 几何 | 窗口移动 / 缩放、全屏、屏幕四边、多屏、100% / 125% / 150% / 200% 缩放（缺设备的组合标未验证） |
| 视觉 | 浅深色、横竖排、无译词、多义项、日文读音、生词、emoji、长文本、稀疏候选 |
| 交互 | 数字 / 空格 / 回车、鼠标、滚轮、分页、旧帧点击、输入法切换、无候选组句 |
| 生命周期 | clientPreedit 有 / 无、ClientUnfocusCommit、reset、失焦、上下文销毁、Server 重启、Fcitx 重启 |
| 隐私 | 普通转 Sensitive / Password / Disable / 未知能力后无残留窗口，私密内容不入日志及词汇记录 |
| 回退 | 后端不可用、渲染失败、字体初始化未完成、配置指定默认面板；不双窗、不重复提交 |

自动化检查覆盖帧映射、文本簇和缩放、命中区域、内存释放、生命周期、回退与隐私；保留现有 CTest。新增渲染 golden 图需人工查看，更新图片不能代替分析回归。

实现阶段继续运行仓库现有 fmt / clippy / Rust 测试和 Fcitx CMake / CTest，CI 命令以 [ci.yml](../../.github/workflows/ci.yml) 为准。新增纯渲染 crate 还需在 macOS / Windows 编译，确认没有 Linux API 泄漏；不要求同一 PR 改两端 UI。真实 GNOME 验收不能由无桌面测试替代。

## 9. 文档同步与完成定义

实现时更新 Linux 用户文档的布局、配置和降级说明；改按键行为才同步按键页。模块落地后更新 `CLAUDE.md` 的目录说明、`crate-notes.md` 和正式渲染设计；当前关于实验渲染器的引用不能继续被当作已落地架构。
